Overview

Ortems Toolbox helps users prepare, review, and load structured demo data for Ortems on SQL Server. The application is organized as a guided set of tabs: first connect to the database, then choose the modules, then fill or import the data, and finally generate and run the SQL script.

Best use case: use this tool when you need to build, adjust, reload, or share an Ortems demo dataset without manually editing SQL scripts.

The tool supports manual data entry, CSV import/export per tab, full workbook import/export, loading data from an existing database, integrity validation, SQL generation, SQL execution, and troubleshooting logs.

Recommended Workflow

Connect to the database.
Open 1. Database, confirm the SQL Server settings, and click DB Connect.
Select the demo modules.
Open 2. Modules and choose which Ortems capabilities are needed for the demo.
Enter, import, or load data.
Use the data tabs to add records, import CSV files, load examples, import a workbook, or load from the connected database.
Run Integrity Check.
Click Integrity Check before generating SQL. Fix any issues shown by the tool.
Generate the SQL script.
Click Generate SQL. The tool switches to the SQL tab and displays the generated script.
Run the SQL on the database.
Click Run on DB. Review the execution log to confirm success.
Save or export your work.
Use Save SQL..., Export Workbook..., or the per-tab Export CSV... buttons when you need a reusable copy.

Screen Layout

Header area

Shows the application title, the beta label, and the connection status. When disconnected, the status is shown as disconnected. After a successful connection, the status confirms the active database context.

Tabbed workspace

Each tab represents a setup area or data category. Some tabs may be enabled or disabled based on the module selection.

Bottom toolbar

Provides the main actions used across the whole application, such as importing/exporting workbooks, loading from the database, clearing data, generating SQL, running SQL, saving SQL, and checking integrity.

Footer

Shows application version information and developer information. The version is useful when reporting issues or confirming that everyone is using the same build.

The Modules tab controls which Ortems capabilities are included in the dataset. Think of it as the demo scope selector.

SRPUse when the demo needs automatic synchronization across BOM levels.

Data Tabs

Most data tabs use the same pattern: a short explanation at the top, a row of action buttons, and a grid. Click a column header in a grid to sort the data. Click the same header again to reverse the order.

TabPurposeMain user notes
3. CalendarsDefines working calendars and shift slots.Days use 1=Monday through 7=Sunday. Times use HH:MM format.
4. MachinesDefines sites, work centers, sections, machines, and related calendars.Each machine belongs to one work center. Calendar references should already exist in Calendars or Capacity.
5. OperationsDefines the operations that machines can execute.Use units D=Days, H=Hours, or C=hundredths of an hour. Interruptible uses 1=Yes and 0=No.
6. RoutingsDefines the sequence of manufacturing phases and operations.Phase codes usually follow a sequence like 10, 20, 30.
7. ItemsDefines raw materials, semi-finished items, and finished goods.Types are MP=Raw Material, SF=Semi-Finished, PF=Finished Good. MP items should not have version or routing.
8. BOMDefines which components are required to produce parent items.Parent items should be manufactured items. Components can be raw materials or manufactured items.
9. Work Orders (WO)Defines production orders with item, routing, version, quantity, and date range.WO ID must be unique. Date format is dd/mm/yyyy hh:mm.
10. WO LinksDefines precedence links between work orders or operations.Common link types include FS, SS, FF, and SF.
11. Secondary ResourcesDefines extra resources required by an operation, such as labor or tooling.Use this when the operation needs something beyond the primary machine.
12. CapacityDefines resource availability and number of concurrent resources.#Resources indicates how many resources are available during that shift slot.
13. Inventory MovementsDefines stock receipts or issues by item and date.Positive quantity means receipt. Negative quantity means issue. Move date format is dd/mm/yyyy.

These tips help avoid common validation errors and reduce rework.

MP itemsLeave Version and Routing ID blank for MP raw material items.
SF/PF itemsProvide a Version and Routing ID for manufactured items.

Workbook and CSV Files

Workbook import/export

Use workbook import/export when you want to move the full dataset as one package. This is the best option for sharing a complete demo setup, keeping backups, or editing across multiple tabs in Excel.

  • Export Workbook... creates a structured file with all tabs.
  • Import Workbook... loads a workbook created by the Toolbox back into the application.
  • The exported workbook can be used as a round-trip file: export, edit, import back.

CSV import/export

Use CSV import/export when you only need to work with one tab at a time.

  • Export CSV... exports only the current tab.
  • Import CSV... imports rows into only the current tab.
  • CSV is practical for targeted edits, but workbook export is safer when the full dataset must stay synchronized.
Before importing a file, make sure the column structure matches the tab you are importing into. Exporting first is often the easiest way to get the expected format.

Integrity Check

The Integrity Check button helps users catch common data issues before generating or running SQL. It checks whether records across tabs are consistent with each other.

What it helps detect

  • Missing references, such as a work order pointing to an item that does not exist.
  • Invalid combinations, such as a routing/version that does not match the item setup.
  • Duplicate keys, such as repeated IDs where uniqueness is required.
  • Required fields left blank.
  • Incorrect date or time formats.
  • MP raw material items with version or routing filled in.
  • Work orders that would not have valid routing phases.

How to use it

Click Integrity Check.
Read the issue summary shown by the tool.
Allow automatic correction only when the proposed fix is clear and acceptable.
Correct any remaining issues manually in the related tabs.
Run Integrity Check again until no blocking issue remains.
A clean integrity result does not replace business validation, but it greatly reduces the chance of avoidable loading errors.

Logs and Verbose Mode

The Toolbox writes log files to the log folder under the application directory. Logs are useful when an operation fails or when someone needs to understand what happened during a session.

FeatureHow to use it
Execution logUse the small log area in the Generate & Run SQL tab for a quick success/failure summary.
Session log fileOpen the latest file in the application log folder when you need more detail.
Verbose ModeEnable it in the Generate & Run SQL tab to include more detailed troubleshooting information, including queries and execution details.
Verbose Mode can create larger logs. Use it during troubleshooting, then turn it off for routine work if detailed logs are not needed.
